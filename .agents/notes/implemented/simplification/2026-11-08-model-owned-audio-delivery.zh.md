# Agent Note: Model-owned audio delivery

Status: implemented

## Problem

模型链接模式已经提供音频优先提示。插件另行下载并直接发送语音会重复 ChatLuna 的发送职责，同时保留另一套下载超时、大小限制和平台发送路径。

## Decision

- 删除 audio-buffer 模式、下载方法、下载专用常量和语音发送分支。只保留 audio-url-model（默认）与 music-card。
- 插件未发布，不提供 audio-buffer / audio-url / file 的兼容转换；配置与工具参数均拒绝已移除模式，客户端不自动修正保存值。
- 候选、单曲和 AI 切换继续返回原始 URL 与音频优先提示，不下载、不发送、不设置 ends。音乐卡片和 QQ 卡片失败时的网页兜底保持不变，直接发送成功的 ends 语义仅适用于卡片选择。
- 网络只负责搜索与 Meting 解析，保留请求取消和有界正文读取；遇到媒体响应时取消正文并返回最终 URL，不等待整曲下载。

## Alternatives considered

仅删除界面选项仍会保留旧配置和工具参数触发的直发路径。继续保留旧默认值会让新配置依赖已删除的功能，因此默认也改为模型链接。

## Consequences

用户明确要求文件或链接时仍由模型遵从，音频无法发送时提示回退原始链接；这是模型指导，不是确定性发送保证。插件不再有音频下载的 15 秒或 64 MiB 限制，后续发送限制属于宿主与适配器。测试覆盖两种模式、已移除模式校验失败、卡片发送、默认模型链接、参数拒绝、正文大小和取消。
