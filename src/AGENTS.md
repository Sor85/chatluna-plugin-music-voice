# src 说明

适用范围：`src/`。同时遵守根 `AGENTS.md`；客户端见 `client/AGENTS.md`，测试见 `tests/AGENTS.md`。

- 基线是 `koishi-plugin-chatluna-music-voice` 0.0.10。保留搜索/选歌语义；不添加旧版没有的聊天命令或 XML voice 处理器。
- 发送方式只保留 `audio-url-model`（默认）与 `music-card`。配置和工具参数只接受这两种模式，不保留旧值别名或自动转换；插件不下载音频或直接发送语音/文件/音频链接，由 ChatLuna 根据模型获得的链接决定发送形式。
- 工具元数据交由 v2 原生工具管理。插件只注册固定标识 `music_voice` 和内置说明，不在 Config 中提供 `toolName` / `toolDescription`，避免与宿主管理重复。
- `searchLimit` 按平台计数；网易云候选在 QQ 前，不排序、不去重。大于 1 时首轮返回候选，即使只有一首；选歌重新搜索相同 query，用本次结果的 1-based index。等于 1 时直接用第一首，忽略 index。
- `allowAISendMode=false` 时工具 Schema 不暴露 sendMode，执行时忽略额外传入的模式；开启后临时模式不改变持久配置。模型链接模式只返回链接，不发送消息。
- 原生工具从可信 `call.routeId` 获取入站会话，不从参数接受机器人或频道身份。工具是 write、副作用不并行、不后台化；卡片选歌发送成功才 `call.end()`，候选、模型链接、错误和单曲卡片直发保留文本返回语义。`MusicResult.endTurn` 只传递内部结束意图，工具结果统一返回文本，不输出自定义静默标记对象。
- `Song` 只保留搜索展示、直链解析和卡片发送实际读取的字段；不解析或校验未使用的时长，避免因无关元数据缺失丢弃可用歌曲。候选结果只返回展示文本，不附带无人读取的原始歌曲数组。
- `ctx.chat.send(session.route, ...)` 是卡片及其兜底消息的唯一发送入口。空 messageIds 视为未发送。卡片只支持 OneBot，QQ 卡片失败回退歌曲网页；网易云卡片不伪装成功。
- 搜索沿用直连与 Apifox 代理竞速；合法空结果等待其他分支，不抢占有效候选。平台间用部分成功结果，全部失败才报服务不可用。请求走 `httpFetch(ctx.http)`。
- Meting 保留八个预设及自定义来源，接受纯 URL、JSON url 和媒体响应；显式设置 netease/tencent 平台，QQ 解析用 mid，卡片用数字 id。
- 网络仅用于搜索和直链解析，具有独立超时、调用/卸载取消及响应正文大小上限；Meting 返回媒体时取消正文，只取最终地址，不下载整曲。发送前检查取消，不在取消后发送兜底消息。
- 模型链接模式的候选与单曲结果附带 `MODEL_LINK_DELIVERY_HINT`：未指定形式时优先音频，明确要求文件/链接时遵从用户，音频不可发送时回退原始链接。可使用该模式时，工具描述与中文说明也包含此提示；不增加插件直发、下载或结束模型循环的行为。
- 模型链接模式直接返回音源解析得到的原始 URL，保留查询参数和编码，不包装本地短链、不代理音频。不提供短链配置或 HTTP 路由，避免模型丢失可直接交给用户的原始地址。
