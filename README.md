# chatluna-plugin-music-voice

为 ChatLuna v2 提供网易云与 QQ 音乐搜索、原始音频链接解析和音乐卡片发送。

## 使用

在插件管理页启用插件后，`music_voice` 会出现在原生工具列表中。当前会话需要允许使用该工具，并具有发送工具所需权限。

自然语言示例：

- 播放一首两只老虎。
- 搜索周杰伦的晴天，选择第二首。
- 搜索一首轻音乐，并返回音频链接。

插件不新增聊天命令。工具是否被调用由当前引擎、模型、预设和工具权限共同决定。

## 搜索与选歌

- 默认只启用网易云音乐，QQ 音乐可单独开启。
- 默认每个平台返回 5 首，候选数量可设为 1–10；启用两个平台时，网易云结果排在 QQ 前面，序号连续。
- 候选数量大于 1 时返回列表：模型链接模式直接附带音频链接，不需要再次调用工具选歌；音乐卡片模式随后用相同搜索词和 `index` 选歌。设为 1 时直接使用第一首。
- 通过 `index` 选歌会重新搜索，不保存候选快照。平台结果变化时，序号可能对应不同歌曲。
- 单个平台请求失败时保留另一平台的结果；全部失败时返回服务不可用提示。

## 发送方式

| 模式 | 行为 |
| --- | --- |
| `audio-url-model`（默认） | 返回音源提供的原始音频链接，由 ChatLuna 根据请求发送音频、文件或链接 |
| `music-card` | 按来源发送网易云或 QQ 音乐卡片，仅支持 OneBot；QQ 卡片失败时回退歌曲网页链接 |

默认关闭 AI 临时切换。开启 `allowAISendMode` 后，模型可通过 `sendMode` 选择本次模式；`default` 使用已保存配置，临时切换不会修改配置。

模型链接模式会提示模型：未指定发送形式时优先使用原始链接发送音频；明确要求文件或链接时遵从用户要求，音频无法发送时回退原始链接。该提示不保证模型一定发送音频，实际发送仍由 ChatLuna 执行。

## 配置

在插件设置页配置搜索来源、候选数量和发送方式。工具名称与描述通过 ChatLuna 的原生工具管理设置。

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `searchLimit` | `5` | 每个平台的候选数量 |
| `enableNetEaseSearch` | `true` | 网易云搜索 |
| `enableQQMusicSearch` | `false` | QQ 音乐搜索 |
| `sourceMode` | `preset` | 使用预设或自定义 Meting API |
| `customMetingApi` | `https://api.injahow.cn/meting/` | 自定义音频直链接口 |
| `allowAISendMode` | `false` | 允许 AI 临时切换模式 |
| `sendMode` | `audio-url-model` | 默认返回原始音频链接给模型 |
| `debug` | `false` | 请求调试日志 |

## 环境与限制

- 需要 ChatLuna v2 与 Node.js 24 或更新版本，不能直接加载到 Koishi 版 ChatLuna。
- 音频发送、转码和文件降级由 ChatLuna 及目标适配器负责；链接可用不代表目标平台一定支持发送。
- 搜索沿用直连与 Apifox 代理竞速，搜索关键词会发送给这些服务。直链使用预设的第三方 Meting 服务或管理员指定接口。
- 歌曲版权、地区、平台策略和第三方接口可用性会影响搜索、直链、后续音频获取或卡片发送；搜索成功不代表音频一定可播放。不会绕过平台权限或购买要求。
- 插件的搜索与直链请求分别有 5 秒超时及响应正文大小限制；后续音频发送的超时、大小和格式限制由 ChatLuna、适配器及目标平台决定。
- 取消调用或卸载插件会停止未完成的搜索和直链请求。
